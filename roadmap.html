Web hidup di hosting

Repo sudah di GitHub, commit c35596a
Selesai
Sudah dikerjakan: git init → 27 berkas di-commit → remote origin disambungkan ke github.com/ukurra/LetsMap → git push -u origin main berhasil. Kredensial akun ukurra sudah tersimpan di Git Credential Manager komputer ini, jadi push berikutnya tidak perlu login ulang.

Yang masih perlu dipastikan

Push ke GitHub baru separuh jalan — repo-nya perlu disambungkan ke Cloudflare Pages supaya benar-benar bisa diakses lewat URL publik. Kalau bagian ini belum dilakukan:

  1. Masuk dash.cloudflare.com. Kalau belum punya akun, daftar dulu (gratis, cukup email).
  2. Sidebar kiri → Workers & Pages → tombol Create → tab Pages → Connect to Git.
  3. Kalau ini pertama kali, Cloudflare minta otorisasi akses ke akun GitHub ukurra — pilih "Only select repositories" lalu centang LetsMap, bukan "All repositories" (lebih aman, tidak kasih akses ke repo lain yang mungkin ada nanti).
  4. Pilih repo ukurra/LetsMap, klik Begin setup.
  5. Di halaman pengaturan build, isi persis begini:
    • Project name: bebas, ini jadi bagian dari URL .pages.dev — misalnya ukurra supaya hasilnya ukurra.pages.dev
    • Production branch: main
    • Framework preset: None
    • Build command: kosongkan — situs ini file statis, tidak ada proses build
    • Build output directory: /
  6. Klik Save and Deploy. Build pertama biasanya selesai 30–90 detik.
Cek: buka https://<project-name>.pages.dev di HP. Landing page tampil, dan menu peramban menawarkan "Add to Home screen" / "Install app" (tanda manifest.webmanifest dan sw.js terbaca). Login belum jalan — itu normal, config.js masih placeholder sampai Tahap 3.
Kalau build gagal:
  • Build output bukan / → Cloudflare mencari index.html di folder yang salah, hasilnya 404 di semua halaman.
  • Build command terisi sesuatu (misal npm run build) → akan gagal karena tidak ada package.json di repo ini. Pastikan benar-benar kosong.

Database & jatah uji coba

Skema sudah dijalankan di Supabase
Selesai
Jatah uji coba (2 misi, 1 proyek olah data) dihitung di server, bukan di peramban — menghapus cache/cookie tidak mengembalikan jatah. Ini sebabnya butuh database sejak awal, bukan nanti-nanti.
Sudah dikerjakan: proyek Supabase dibuat, seluruh isi supabase-schema.sql dijalankan lewat SQL Editor.

Yang perlu dicek ulang supaya yakin benar-benar siap

  1. Supabase dashboard → Table Editor (sidebar kiri). Pastikan ada 2 tabel: profiles (kolom plan, pro_until, missions_used, projects_used) dan missions.
  2. Database → Functions. Harus ada ukurra_new_user dan ukurra_use_quota. Kalau tidak ada, skemanya belum sepenuhnya jalan — jalankan ulang supabase-schema.sql (aman diulang, semua perintahnya pakai create or replace / if not exists).
  3. Authentication → Policies, tabel profiles harus punya policy "baca profil sendiri" dan RLS berstatus Enabled (ikon gembok hijau). Tanpa RLS aktif, siapa pun yang punya anon key bisa membaca profil orang lain.
  4. Catat Project Settings → API → Project URL dan anon public key — dua nilai ini dipakai persis sama di Tahap 3 (web) dan Tahap 5b (desktop).
Cek paling meyakinkan: di SQL Editor, jalankan select * from public.profiles; — hasilnya boleh kosong (belum ada yang login), tapi query-nya harus sukses tanpa error "relation does not exist".
Catatan free tier Supabase: proyek yang tidak disentuh 7 hari berturut-turut akan otomatis dijeda (statusnya "Paused" di dashboard) dan harus dibangunkan manual lewat tombol "Restore". Selama trafik masih sepi, buka dashboard-nya minimal sekali seminggu supaya tidak kaget tiba-tiba login gagal.

Login Google

Teruji dengan login sungguhan 2026-11-03
Selesai
Sudah dikerjakan: OAuth Client ID dibuat, redirect URI Supabase terdaftar di Google Cloud Console (sempat salah → redirect_uri_mismatch → diperbaiki), Client ID/Secret tersambung ke Supabase, config.js terisi. Login dengan akun Google sungguhan berhasil, baris baru muncul di tabel profiles. Masih mode Testing di Google (maksimal 100 test user) — publish ke Production ada di Tahap 7.
Alurnya: peramban → Google → Supabase → kembali ke situs. Yang didaftarkan ke Google adalah alamat Supabase, bukan alamat ukurra.com — ini satu kalimat yang paling sering bikin orang salah isi kolom.

A. Buat proyek & consent screen di Google Cloud

  1. Buka console.cloud.google.com, login dengan akun Google yang akan jadi pemilik proyek (sebaiknya akun khusus ukurra, bukan akun pribadi, supaya kepemilikan jelas kalau nanti ada yang bantu kelola).
  2. Pojok kiri atas, dropdown proyek → New Project → nama Ukurra → Create.
  3. Sidebar → APIs & Services → OAuth consent screen.
  4. User type: External (karena ini produk publik, bukan internal organisasi Google Workspace).
  5. Isi: App name Ukurra, User support email (email kamu), App logo (opsional tapi disarankan — pakai assets/icons/icon-512.png dari repo), Developer contact email.
  6. Kolom Privacy Policy URL dan Terms of Service URL — kosongkan dulu, baru diisi setelah Tahap 7 selesai. Tanpa dua URL ini nanti, app tidak bisa di-publish ke production (lihat Tahap 7).
  7. Scopes: tambahkan .../auth/userinfo.email, .../auth/userinfo.profile, openid. Ketiganya tergolong non-sensitif — ini penting, dijelaskan lebih lanjut di Tahap 7.
  8. Test users: tambahkan emailmu sendiri dulu supaya bisa dites sebelum publish.

B. Buat OAuth Client ID

  1. Credentials → Create Credentials → OAuth client ID.
  2. Application type: Web application.
  3. Authorized redirect URIs — isi satu baris persis ini, ganti bagian ref dengan punyamu sendiri:
    • https://<ref-proyekmu>.supabase.co/auth/v1/callback
    <ref-proyekmu> ada di Supabase → Project Settings → API → Project URL (bagian sebelum .supabase.co).
  4. Create. Simpan Client ID dan Client Secret yang muncul — Client Secret cuma ditampilkan sekali, kalau terlewat harus generate ulang.

C. Sambungkan ke Supabase

  1. Supabase dashboard → Authentication → Providers → cari Google di daftar, klik untuk expand.
  2. Toggle Enable Sign in with Google jadi aktif.
  3. Tempel Client ID dan Client Secret dari langkah B. Save.
  4. Authentication → URL Configuration:
    • Site URL: https://<project-name>.pages.dev (nanti diganti https://ukurra.com di Tahap 4)
    • Redirect URLs, tambahkan dua baris:
      • https://<project-name>.pages.dev/**
      • ukurra://auth — ini dipakai aplikasi desktop. Tanpa baris ini, login di Ukurra Studio akan ditolak Supabase dengan pesan redirect tidak dikenal.

D. Isi konfigurasi web

  1. Buka assets/js/config.js di repo lokal.
  2. Isi SUPABASE_URL dan SUPABASE_ANON_KEY — ambil dari Supabase → Project Settings → API. Jangan pernah pakai service_role key di sini — yang benar anon public key.
  3. git add assets/js/config.js && git commit -m "Sambungkan Supabase" && git push — Cloudflare otomatis deploy ulang begitu push masuk, biasanya hidup dalam 1–2 menit.
Cek: buka situs, klik login, pilih akun Google (yang sudah ditambahkan sebagai test user). Setelah redirect balik, di Supabase → Table Editor → profiles harus muncul satu baris baru berisi emailmu, plan = free, missions_used = 0. Buat satu misi lalu ekspor, muat ulang halaman — angka missions_used harus jadi 1.
Error yang sering muncul:
  • "redirect_uri_mismatch" dari Google — redirect URI di Google Cloud Console tidak persis sama dengan URL Supabase (beda huruf besar/kecil, trailing slash, atau http vs https juga dihitung beda).
  • Login "berhasil" tapi kembali ke halaman kosong/putih — Site URL atau Redirect URLs di Supabase belum diisi dengan benar, atau belum menambahkan /** di akhir.
  • "Access blocked: this app's request is invalid" — akun yang dipakai login belum ditambahkan sebagai Test user (normal selama masih mode Testing, selesai di Tahap 7).

Domain ukurra.com

Hidup, HTTPS aktif, login berhasil dari domain ini
Selesai
Sudah dikerjakan: domain dibeli lewat Cloudflare Registrar, disambungkan sebagai custom domain ke Cloudflare Pages, HTTPS otomatis aktif, Site URL & Redirect URLs di Supabase sudah diarahkan ke https://ukurra.com.
  1. Cloudflare dashboard → Domain Registration → Register Domain, cari ukurra.com. Cloudflare menjual di harga modal (tanpa markup), biasanya salah satu yang termurah dibanding registrar lain.
  2. Checkout, bayar (kartu kredit/debit). WHOIS privacy otomatis aktif di Cloudflare, gratis — data pendaftar tidak terbuka publik.
  3. Domain otomatis masuk ke akun Cloudflare yang sama. Tidak perlu urus nameserver manual kalau beli langsung di Cloudflare.
  4. Kembali ke Workers & Pages → proyekmu → Custom domains → Set up a custom domain, masukkan ukurra.com. DNS record dan sertifikat HTTPS terpasang otomatis dalam beberapa menit.
  5. Ulangi untuk www.ukurra.com kalau mau keduanya aktif (opsional, tapi disarankan supaya orang yang ketik "www." tidak mentok error).
  6. Supabase → Authentication → URL Configuration: ubah Site URL jadi https://ukurra.com, tambahkan https://ukurra.com/** ke Redirect URLs. Jangan hapus baris .pages.dev yang lama — biarkan tetap ada sebagai cadangan selama masa transisi.
Cek: https://ukurra.com terbuka dengan kunci HTTPS (bukan peringatan "Not Secure"), dan login Google masih berhasil dari alamat baru ini.
Domain .id: kalau nanti juga mau ukurra.id, Cloudflare tidak menjual domain .id — perlu registrar Indonesia (Domainesia, Rumahweb, dll.), lalu arahkan nameserver-nya ke Cloudflare supaya tetap bisa dikelola dari satu dashboard.

Pembayaran

Mayar.id · aktivasi otomatis teruji transaksi sungguhan
Selesai
Sudah dikerjakan: dua produk digital dibuat di Mayar (Tahunan Rp 599.000, Bulanan Rp 69.000), masing-masing dengan link pembayaran langsung sendiri di CHECKOUT_URL / CHECKOUT_URL_MONTHLY (config.js web & desktop). Kartu harga landing page dan modal upgrade di dalam app punya tombol terpisah untuk tiap paket — bukan satu tombol dengan parameter ?plan=, karena Mayar tidak membacanya.

Aktivasi Pro otomatis lewat Supabase Edge Function supabase/functions/mayar-webhook: menerima event payment.received dari Mayar, mencocokkan produk lewat productId asli (bukan nominal — nominal bisa berubah kalau biaya admin ditanggung pembeli), lalu set plan='pro' pada baris profiles yang emailnya cocok. Diuji dengan transaksi Rp 69.000 sungguhan 2026-11-03 — berhasil end-to-end.

Kenapa bukan tanda tangan/HMAC

Mayar tidak mendokumentasikan skema verifikasi tanda tangan untuk webhook-nya (dicek di docs.mayar.id/integration/webhook). Sebagai gantinya, URL function sendiri berisi token rahasia (?secret=...) sebagai pembuktian keaslian — disimpan sebagai secret Supabase MAYAR_WEBHOOK_SECRET, ditempel ke URL webhook di dashboard Mayar → Integration → Webhook.

Batasan yang masih ada: pembeli harus login dulu

Aktivasi mencocokkan lewat email pada tabel profiles — baris itu baru ada setelah seseorang login Google minimal sekali (Tahap 3). Kalau ada yang bayar sebelum pernah login, function mencatat jelas di log siapa yang perlu diaktifkan manual, tidak gagal diam-diam. Aktivasi manualnya:

update public.profiles set plan = 'pro', pro_until = now() + interval '1 month' where email = 'pembeli@contoh.com';

(ganti 1 month jadi 1 year untuk paket Tahunan). Perintah ini juga ada di bagian bawah supabase-schema.sql.

Cek: di Mayar dashboard → Integration → Webhook, status harus "aktif". Kalau ada transaksi baru masuk, Supabase → Edge Functions → mayar-webhook → Logs harus menunjukkan berhasil aktifkan Pro, dan tabel profiles pembelinya berubah jadi plan = 'pro' otomatis tanpa disentuh manual.
Kalau mau ganti/tambah produk nanti: ID produk Mayar dihardcode di PAKET pada supabase/functions/mayar-webhook/index.ts (bukan dibaca otomatis dari Mayar) — produk baru atau ganti harga perlu update manual di file itu lalu supabase functions deploy mayar-webhook ulang.

Bagikan installer desktop

Cloudflare R2 · installer ± 600–800 MB
Belum di-hosting
Ukuran terukur: Ukurra Studio 487 MB + OpenDroneMap 1,1 GB setelah terpasang. Installer gabungan setelah kompresi NSIS sekitar 600–800 MB — jauh di atas batas 25 MiB per berkas di Cloudflare Pages, jadi tidak boleh ikut masuk repo web. R2 dipilih karena 10 GB gratis dan yang paling menentukan: unduhan tidak ditagih bandwidth — dengan installer seberat ini, 100 pengunduh saja sudah 70 GB trafik.
  1. Cloudflare dashboard → R2 Object Storage → Create bucket, nama ukurra-rilis, lokasi otomatis (biarkan default).
  2. Upload Ukurra-Studio-Setup.exe — lewat dashboard (drag & drop, cukup untuk sesekali) atau wrangler CLI kalau mau upload berulang lewat skrip.
  3. Masuk bucket → Settings → Public access → Connect Domain, masukkan unduh.ukurra.com. Butuh domain ukurra.com sudah aktif di Cloudflare (Tahap 4).
  4. Tunggu beberapa menit sampai DNS dan sertifikat terpasang.

Tautan jadinya https://unduh.ukurra.com/Ukurra-Studio-Setup.exe — tombol "Unduh Ukurra Studio" di landing page sudah dipasang dan mengarah persis ke tautan ini. Tidak perlu sentuh kode lagi; begitu 4 langkah di atas selesai, tombolnya langsung hidup.

Unduhan sengaja tidak dikunci di balik pembayaran — siapa pun boleh mengunduh dan mencoba. Batas 1 proyek olah data gratis sudah ditegakkan di dalam aplikasi sendiri lewat akun Google + Supabase (Tahap 5b), jadi mengunci tautan unduhan hanya akan menyusahkan pengguna sah tanpa benar-benar mencegah pembajakan — installer yang bocor tetap butuh login untuk dipakai lebih dari satu proyek.
Cek: klik tombol "Unduh Ukurra Studio" di landing page yang sudah live, installer-nya benar-benar terunduh (bukan 404).
Alternatif: GitHub Releases juga gratis dan tanpa batas bandwidth, tapi tautannya selalu publik sepenuhnya — kurang cocok kalau nanti ingin membedakan versi/akses tertentu. R2 tetap pilihan utama.

Halaman Privasi & Syarat, lalu publish OAuth

Wajib supaya tidak perlu daftarkan akun satu-satu
Belum ada
privacy.html dan terms.html belum ada di proyek ini. Tanpa dua halaman ini, OAuth consent screen di Google Cloud Console tertahan di status Testing — hanya akun yang didaftarkan manual satu-satu (maksimal 100) yang bisa login. Produk tidak bisa dipakai publik tanpa melewati tahap ini.

A. Tulis dua halamannya

  1. privacy.html — jelaskan: data apa yang dikumpulkan (email & nama dari Google, data misi/proyek yang disimpan), untuk apa dipakai, di mana disimpan (Supabase, server Singapura), berapa lama disimpan, dan cara pengguna minta akunnya dihapus (misalnya lewat email dukungan).
  2. terms.html — syarat pakai layanan, batasan tanggung jawab (hasil pengukuran bersifat estimasi, bukan jaminan akurasi survei legal), kebijakan jatah uji coba & langganan, kebijakan pembatalan.
  3. Taruh keduanya di root proyek (sejajar dengan index.html), style sederhana sudah cukup — tidak perlu desain rumit, yang penting isinya jelas dan jujur.

B. Terbitkan & sambungkan ke Google

  1. git add privacy.html terms.html && git commit -m "Tambah halaman Privasi & Syarat" && git push — tunggu Cloudflare Pages selesai deploy ulang.
  2. Google Cloud Console → APIs & Services → OAuth consent screen, isi:
    • Privacy Policy URL: https://ukurra.com/privacy.html
    • Terms of Service URL: https://ukurra.com/terms.html
  3. Klik tombol PUBLISH APP — status berubah dari "Testing" ke "In production".
Kabar baiknya: publish ini langsung aktif seketika, tidak perlu menunggu tim review Google. Itu karena scope yang dipakai (email, profile, openid) tergolong non-sensitif. Proses review manual Google yang bisa makan waktu berminggu-minggu (butuh video demo, audit kebijakan privasi, verifikasi domain lewat Search Console) hanya berlaku untuk app yang minta scope sensitif/restricted (akses Gmail, Drive, Kalender, dll.) — Ukurra tidak menyentuh scope itu sama sekali, jadi publish-nya murni klik tombol. Sebagai efek sampingnya, pengguna juga tidak akan melihat layar peringatan "Google belum memverifikasi app ini" — peringatan itu cuma muncul untuk app dengan scope sensitif.
Cek paling meyakinkan: minta teman atau pakai akun Google kedua yang belum pernah kamu tambahkan sebagai test user, coba login. Kalau berhasil masuk tanpa ditolak, berarti status sudah "In production" dan siapa pun bisa pakai.
Kalau tombol Publish tidak bisa diklik / muncul peringatan:
  • Field wajib di consent screen belum lengkap — cek lagi App name, support email, developer email, dan dua URL legal sudah semua terisi.
  • Tampilan menu Google Cloud Console bisa berubah sewaktu-waktu — kalau nama tombol/field tidak persis sama saat kamu buka, cari istilah "Publish app" atau status "Testing / In production" di halaman OAuth consent screen, intinya tetap sama.

Boleh dikerjakan belakangan, tidak menghalangi peluncuran teknis

Tinjauan hukum soal lisensi AGPL OpenDroneMap (ODM dipanggil sebagai program terpisah lewat run.bat, tidak pernah dimodifikasi — polanya sudah dirancang untuk menjaga kewajiban AGPL tetap pada ODM sendiri) sebaiknya selesai sebelum rupiah pertama masuk, tapi tidak menghalangi Tahap 1–7 di atas berjalan sama sekali. Kerjakan paralel, kapan saja sebelum benar-benar menerima pembayaran pertama — bukan sebagai gerbang yang menahan deploy.

Setelah tahap 1–7 selesai

Siapa pun bisa buka ukurra.com, login dengan akun Google mana pun tanpa didaftarkan dulu, pakai mission planner dengan jatah 2 misi gratis, unduh Ukurra Studio dan olah 1 proyek gratis, lalu berlangganan Standard lewat Lynk/Mayar kalau jatahnya habis — semua tanpa campur tangan manual dari kamu, kecuali mengaktifkan status Standard lewat SQL Editor sampai webhook pembayaran dibangun.
